# Review extraction prompt — v1

You are extracting structured board game review records from raw text.
The input may be a single review, an article discussing several games or
reviewers, or an editorial roundup citing other critics. For each
distinct (reviewer, game) pair you find evidence for, produce one
`ExtractedReview` record.

## What counts as a review

A review is a substantive opinion about a specific board game by an
identifiable reviewer. Brief mentions ("we also played X this week") do
**not** count. If a reviewer is quoted by a roundup author, the quote
attributes the review to the quoted reviewer, not the roundup author.

## Field-by-field guidance

- `game_title` — the title as it appears in the text. Do not normalise
  ("Catan", not "The Settlers of Catan", if the text says "Catan"). The
  matching layer that follows handles canonicalisation.

- `reviewer_name` — the human-readable name. If only an outlet is given
  ("the SU&SD team"), use the outlet name as the reviewer name and leave
  it that way.

- `reviewer_id` — lower_snake_case identifier derived from the name. Be
  consistent within a single document, but understand that downstream
  resolution against the critic registry may override this.

- `outlet` — the publication, channel, or site. Null if the reviewer
  publishes independently with no outlet.

- `original_url` — if the text references or links to the original
  review on the reviewer's own site, extract that URL. Null otherwise.

- `original_date` — when the review was originally published, in
  ISO-8601 (YYYY-MM-DD) where possible. Null if not stated.

- `language` — ISO 639-1 code for the language of the review itself
  (`en`, `de`, `fr`, etc.). Identify from the text, not from assumptions
  about the source.

- `score_declared` — the score or verdict as the critic actually stated
  it, verbatim. Examples: `"4/5"`, `"8.5"`, `"Recommended"`,
  `"Tier S"`. **Null** if the critic did not declare a score. Do not
  fabricate a score from sentiment.

- `rating_inferred` — a 1–10 integer rating derived from the score
  and/or text. Always populated. Use this rubric:
  - 9–10: Glowing, exceptional, "must play"
  - 7–8:  Very positive, minor flaws
  - 5–6:  Mixed or neutral, significant reservations
  - 3–4:  Mostly negative, "disappointing"
  - 1–2:  Extremely negative, "avoid"

- `sentiment` — `positive`, `neutral`, or `negative`. Should align with
  `rating_inferred` (≥7 positive, 5–6 neutral, ≤4 negative) unless the
  text gives you a clear reason to diverge.

- `quote_verbatim` — a single verbatim pull-quote from the review, in
  the critic's own words. **Strict 15-word limit.** Choose a quote that
  characterises the critic's view. If no quote fits within 15 words,
  set this to null — do not paraphrase into the field, do not truncate
  mid-clause.

- `summary` — 1–3 sentences in your own words capturing the critic's
  view, including key praise and criticism. Must be a paraphrase, never
  a quote. Do not reproduce more than incidental short phrases from the
  source text.

## What to skip

- Bare mentions without opinion ("we played X").
- Unverifiable attributions ("someone said X is great").
- Reviews of expansions when the text is unclear which base game is
  meant — flag by setting `game_title` to the most specific name you
  saw, and let the matcher decide.

## Output format

Return a single `ExtractedReviewList` JSON object with a `reviews` array.
If the text contains no extractable reviews, return an empty array — do
not invent reviews to pad the output.
